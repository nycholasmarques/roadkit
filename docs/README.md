# Documentação

Aqui está o que eu gostaria de ter lido quando comecei a usar o Roadkit. Não é um manual de referência, é mais uma conversa sobre como as coisas funcionam e por que estão do jeito que estão.

Se é a primeira vez, comece pelo passeio na interface. Se você só quer criar um roadmap, pule para o segundo.

| Texto | Do que trata |
|---|---|
| [Usando a interface](usando-a-interface.md) | A tela, o mapa, o kanban, como o progresso é marcado e onde ficam os ajustes |
| [Criando roadmaps](criar-roadmaps.md) | Três jeitos de criar um, e o que faz um roadmap ser bom de usar |
| [Criando com IA](criar-com-ia.md) | O botão "Criar com IA" e a skill para agentes de código |
| [Como funciona](como-funciona.md) | O que roda onde, onde cada coisa é guardada e como o código se organiza |
| [Docker e rede](docker-e-rede.md) | Subir com Compose, volumes, backup e abrir para outros aparelhos |
| [Formato do JSON](SCHEMA.md) | Referência de cada campo de um roadmap |
| [Publicando versões](publicando-versoes.md) | Versionamento, releases automáticas, CI e proteção da main |

As imagens e os GIFs que aparecem nos textos ficam em `media/` e são gerados por um script, então não precisa refazer à mão quando a interface mudar. O [final de "Como funciona"](como-funciona.md#as-imagens-da-documentação) explica como.
